1. Ringkasan

Smart Neonatal Incubator Sentinel adalah prototipe sistem pemantauan inkubator bayi (neonatus) berbasis Raspberry Pi 5. Sistem membaca suhu dan kelembapan (DHT11), gerakan bayi (PIR HC-SR501), dan suara/tangisan (modul suara LM393), lalu menampilkannya di dashboard web untuk perawat dan mengendalikan indikator serta buzzer di boks inkubator.

Tiga prinsip utama desain:

  1. Alarm suhu dan kelembapan hening di boks. LED merah berkedip, tetapi buzzer boks tidak berbunyi agar bayi tidak terpapar bising. Peringatan suara hanya muncul di perangkat perawat melalui Web Audio API.
  2. Pemeriksaan inaktivitas. Jika PIR tidak mendeteksi gerakan selama 2 menit, buzzer boks berbunyi untuk memastikan kondisi bayi dan membangunkannya. Buzzer yang sama dipakai untuk membangunkan bayi pada jadwal menyusu.
  3. Bukti kehadiran fisik (physical proof-of-presence). Buzzer boks hanya dapat dimatikan dengan menahan tombol fisik di inkubator. Tidak ada perintah mute dari web.

Catatan penting: sistem ini adalah prototipe edukasi, bukan perangkat medis. PIR hanya mendeteksi gerakan, bukan napas, sehingga fitur ini disebut pemeriksaan inaktivitas, bukan deteksi apnea.

No Aturan

3.2 Model Eksekusi

  • Thread hardware-engine: loop setiap 0,1 detik. DHT11 dibaca tiap 2 detik (batas sampling sensor). PIR dan sensor suara dibaca tiap siklus.
  • Thread Flask: melayani HTTP (threaded=True). Dashboard polling /api/status tiap 1 detik.
  • Callback GPIO (gpiozero): tombol (when_held), PIR dan sensor suara (when_activated) berjalan di thread gpiozero.
  • Sinkronisasi: seluruh state bersama dilindungi satu threading.RLock. Waktu memakai time.monotonic() agar kebal terhadap perubahan jam sistem.
  • Aktuator hanya diubah saat status berganti (_applied_state), sehingga pola kedip tidak ter-reset tiap siklus.

Catatan keselamatan wiring

  • GPIO Raspberry Pi bekerja pada logika 3,3 V dan tidak toleran 5 V. Modul LM393 yang disuplai 5 V dapat mengeluarkan 5 V pada pin DO. Suplai modul dari 3,3 V, atau gunakan pembagi tegangan/level shifter bila harus 5 V.
  • Buzzer bare (tanpa modul transistor) dapat menarik arus melebihi batas aman GPIO. Gunakan modul buzzer atau transistor.
  • Satu pin GPIO hanya boleh dipakai satu perangkat. Program akan berhenti dengan pesan KONFLIK PIN bila Config memuat pin ganda.
  • Jika wiring fisik Anda berbeda dari tabel ini, ubah nomor pin di class Config, bukan sebaliknya.

5. Finite State Machine (FSM)

5.1 Daftar Status dan Prioritas

Sistem selalu berada di tepat satu status, dipilih dari kondisi aktif dengan prioritas tertinggi (1 = tertinggi):

Prioritas Status Kondisi pemicu
1 CODE_BLUE Perintah dari dashboard
2 INACTIVITY_ALERT Tidak ada gerak PIR ≥ 120 detik
3 FEEDING_WAKE Perintah "Bangunkan Bayi" dari dashboard
4 THERMAL_HAZARD Suhu ≥ 34,0 °C atau ≤ 31,0 °C
5 HUMIDITY_HAZARD Kelembapan ≥ 80 % atau ≤ 50 %
6 SENSOR_FAULT DHT11 tanpa data valid > 10 detik
7 CRYING_DISTRESS Sensor suara aktif (ditahan 3 detik)
8 IDLE_NORMAL Tidak ada kondisi di atas

Karena hanya satu status yang tampil di LED, dashboard juga menampilkan semua peringatan aktif sekaligus (chip active_alerts) dan memainkan alarm web sesuai flag masing-masing, sehingga bahaya suhu tidak "tertutup" oleh status berprioritas lebih tinggi.

5.4 Histeresis

Alarm menyala bila nilai berada di luar [batas bawah, batas atas], tetapi baru padam setelah nilai kembali ke pita dalam (batas bawah + H hingga batas atas − H). Ini mencegah alarm berkedip saat nilai berfluktuasi di sekitar batas.

@staticmethod
def _band_alarm(active, value, low, high, hyst):
    if not active:
        return value >= high or value <= low
    return not (low + hyst <= value <= high - hyst)

7.5 Cuplikan Logika Inti

Pola aktuator

def apply_pattern(self, state):
    g, r, b = self.led_hijau, self.led_merah, self.buzzer
    g.off(); r.off(); b.off()
    if state is State.IDLE_NORMAL:
        g.on()
    elif state is State.EMERGENCY:
        r.blink(on_time=0.1, off_time=0.1)
        b.beep(on_time=0.1, off_time=0.1)
    elif state in (State.INACTIVITY_ALERT, State.FEEDING_WAKE):
        r.blink(on_time=0.15, off_time=0.15)
        b.beep(on_time=0.4, off_time=0.4)
    else:  # THERMAL, HUMIDITY, SENSOR_FAULT, CRYING
        r.blink(on_time=0.15, off_time=0.15)

Resolusi status

def _resolve_state(self):
    if self.emergency:      return State.EMERGENCY
    if self.inactivity:     return State.INACTIVITY_ALERT
    if self.feeding_wake:   return State.FEEDING_WAKE
    if self.thermal_alarm:  return State.THERMAL_HAZARD
    if self.humidity_alarm: return State.HUMIDITY_HAZARD
    if self.sensor_fault:   return State.SENSOR_FAULT
    if self.cry_active:     return State.CRYING_DISTRESS
    return State.IDLE_NORMAL

Tombol fisik sebagai satu-satunya pemadam buzzer

def _on_button_confirmed(self):
    with self.lock:
        if self.inactivity or self.feeding_wake or self.emergency:
            self.inactivity = self.feeding_wake = self.emergency = False
            self.last_motion = time.monotonic()
            self._chirp_requested = True
            self.log("info", "VERIFIKASI FISIK: Perawat hadir di lokasi...")

8.2 POST /api/control

Body JSON: {"action": "<nama>"}. Bila INCUBATOR_TOKEN di-set, sertakan header X-Auth-Token.

action Hasil
wake_baby Mengaktifkan FEEDING_WAKE (buzzer boks bunyi). 409 bila buzzer sudah aktif atau CODE BLUE berjalan
emergency_alert Mengaktifkan CODE BLUE. 409 bila sudah aktif
mute, unmute, stop_buzzer, clear_emergency Ditolak 403: buzzer hanya dapat dimatikan via tombol fisik
update_thresholds, update_humidity_thresholds Ditolak 403: ambang bersifat default tetap
lainnya 400 aksi tidak dikenal

Respons sukses: {"status": "success", "message": "...", "data": { ...snapshot... }}. Kode galat: 400 (format/aksi salah), 401 (token salah), 403 (dilarang protokol), 409 (konflik status).

Perilaku Audio Monitor (Web Audio API)

  • Browser mewajibkan interaksi pengguna sebelum audio, sehingga tombol harus diklik sekali.
  • Bunyi hanya terjadi bila ada alarm: koneksi putus > CODE BLUE > inaktivitas > suhu > kelembapan (nada prioritas tertinggi saja). Berulang dengan jeda, berhenti otomatis saat alarm padam.
  • Dapat dimatikan kapan saja dengan klik tombol yang sama.
  • Jadwal susu dan tangisan hanya notifikasi visual.
  • Keterbatasan: halaman harus terbuka dan perangkat tidak terkunci/tertidur. Peramban dapat membatasi tab latar belakang.

Token: jika auth_required bernilai true, dashboard meminta token sekali (disimpan di sessionStorage tab).

11.3 Pengujian Simulasi

Dengan INCUBATOR_SIM=1, logika FSM (histeresis, timer inaktivitas, prioritas status, penolakan perintah mute, autentikasi token, pola aktuator) dapat diuji otomatis tanpa hardware dengan memanggil IncubatorSentinel._update_locked() dan Flask test client. Simulasi hanya memverifikasi logika, bukan wiring atau perilaku sensor fisik.

13. Keterbatasan dan Catatan Keselamatan

  1. Bukan perangkat medis. Tidak memenuhi standar seperti IEC 60601-1-8 (sistem alarm) dan IEC 60601-2-19 (inkubator bayi). Jangan dipakai pada pasien nyata.
  2. PIR tidak mengukur napas. Diam tidak sama dengan apnea. Untuk deteksi pernapasan diperlukan sensor lain (mis. piezo, radar, pulse oximeter).
  3. DHT11 kurang presisi (±2 °C, ±5 % RH, resolusi 1 satuan). Untuk aplikasi serius gunakan DS18B20 atau SHT31.
  4. Sensor suara digital tidak mengenali tangisan, hanya suara melampaui ambang (tepukan dan pintu juga terdeteksi). Pengenalan tangisan memerlukan analisis frekuensi/ML.
  5. Alarm bergantung pada browser. Jika perangkat perawat tertidur atau halaman tertutup, alarm suhu/kelembapan hanya terlihat dari LED di boks. Notifikasi push eksternal dapat menjadi pengembangan lanjutan.
  6. Kompromi desain: membungkam alarm audio lokal untuk suhu bertentangan dengan praktik standar alarm medis yang mewajibkan penanda audible. Keputusan ini sengaja diambil demi perlindungan pendengaran bayi dan harus dibahas sebagai trade-off.
  7. Keamanan jaringan: tanpa INCUBATOR_TOKEN, siapa pun di jaringan yang sama dapat memicu Bangunkan Bayi atau CODE BLUE. Gunakan token dan jaringan tertutup. Server Flask bawaan bukan server produksi (tanpa HTTPS).
  8. Raspberry Pi bukan sistem waktu-nyata keras. Penjadwalan Linux tidak menjamin tenggat waktu pasti.
  9. Jika Pi mati atau hang, semua indikator mati. Watchdog perangkat keras dan catu daya cadangan belum ada.
